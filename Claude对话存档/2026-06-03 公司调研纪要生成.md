>
> **Tool knowledge**
>
> For docx generation in this environment, the `docx` npm package is available globally and does not need local installation — `node -e "require('docx')"` confirms availability. The critical failure mode when building Chinese-language documents is quotation mark conflicts: full-width Chinese quotes `"` `"` and stray ASCII `"` characters embedded inside Chinese string literals in the JS build script will silently break parsing. The working solution is to use 「」 bracket quotes exclusively for any in-text Chinese quotation inside the script's string content, reserving ASCII `"` only as JS string delimiters. Validation uses `python /mnt/skills/public/docx/scripts/office/validate.py <file>.docx`. Visual page rendering for spot-checking uses the pipeline: `soffice.py --headless --convert-to pdf` then `pdftoppm -jpeg -r 90`. The `extract-text` command works for reading uploaded `.docx` source files. For skill packaging, `python -m scripts.package_skill <skill-dir> <output-dir>` requires the output directory as a positional second argument, not a flag, and must point to a writable path such as `/mnt/user-data/outputs`.
