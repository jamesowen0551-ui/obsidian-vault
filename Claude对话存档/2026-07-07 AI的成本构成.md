## AI成本全景框架

可以用"三层结构"来理解：**基础设施层 → 模型层 → 应用层**，每层的成本主体、性质和驱动因素都不一样。

---

### 第一层：基础设施（AI Infra）
**成本主体：云厂商、数据中心运营商、超算集群**

这是整个AI产业最重的资本开支，性质是**固定成本+长周期投入**。

**算力硬件**
- GPU/TPU/NPU采购：核心是Nvidia H100/B200系列，单卡售价数万美元，大型集群动辄数十亿美元
- 自研芯片：Google TPU、AWS Trainium、微软Maia，目的是降低对Nvidia的依赖

**数据中心**
- 土建、机柜、散热（液冷占比快速上升）
- 电力：这是当前最紧张的瓶颈。全球能源成本上升正在引发对数据中心增长的反弹，推动低成本能源支持政策出台，并促使数据中心项目采用"离网"供电策略。超算集群的PUE（电能利用效率）直接影响运营成本结构

**网络互联**
- 高速InfiniBand/NVLink互联，训练大模型时GPU间通信带宽是关键瓶颈

**量级参考：** 微软计划投入800亿美元用于数据中心建设，亚马逊预计投入超750亿美元，Meta传闻将花费逾2000亿美元。

---

### 第二层：模型层（训练 + 推理）
**成本主体：OpenAI、Anthropic、Google DeepMind等模型厂商**

这一层分两块，性质完全不同：

**① 训练成本（一次性大额支出）**
- 预训练：调用大量GPU算力跑数周到数月，GPT-4级别的模型训练成本估算在1亿美元量级
- 后训练（RLHF/DPO/SFT）：涉及大量人工标注，人力成本显著
- 数据成本：高质量语料采购、清洗、合规

**② 推理成本（持续流动性支出）**
- 每次用户调用都消耗计算资源，按Token计费
- 推理成本 = GPU机时 × Token数量，上下文越长、模型越大，成本越高
- 随着AI模型从单一对话向智能体形态演进，Token消耗和推理费用可能呈指数级增长，给商业化落地带来严峻挑战。

**成本下降的趋势：**
受小模型技术突破驱动，AI推理成本在2022至2024年间下降约280倍，极大降低了应用门槛。这背后的机制包括：模型蒸馏、量化压缩、MoE架构（如DeepSeek只激活部分参数）、KV Cache优化等。

**盈利困境：**
OpenAI预计2025年收入将达到127亿美元，但运营成本极高，预计2026年亏损可能达到140亿美元，2023至2028年累计亏损可能高达440亿美元，预计到2029年才可能实现盈利。

---

### 第三层：应用层（企业采购 + 部署）
**成本主体：使用AI的企业**

这一层成本结构更接近传统IT采购，但有新的特殊项：

| 成本类型 | 具体内容 |
|---|---|
| **API调用费** | 按token付费，使用越多越贵，规模化后是大头 |
| **模型订阅/License** | SaaS型产品（Copilot、Claude for Work等）按席位收费 |
| **部署成本** | 私有化部署需要自建GPU服务器或租用云计算资源 |
| **集成开发成本** | 将AI接入已有系统的工程人力 |
| **数据治理成本** | RAG知识库建设、数据清洗、安全隔离 |
| **合规与安全** | AI审计、输出过滤、监管合规 |
| **再培训成本** | 企业和政府正推出广泛的再培训计划，以应对AI驱动的就业变化。 |

---

### 宏观投资视角的关键判断

整个AI产业利润分配存在严重失衡——Nvidia几乎攫取了市场近九成的利润，下游很多应用开发和模型训练企业需支付天价算力成本，却难以实现盈利。

这决定了当前阶段的投资逻辑：**基础设施（尤其是芯片）是最确定的受益者，模型层烧钱竞争、盈利遥远，应用层分化剧烈、部分垂类已跑出正向现金流。**

成本曲线往下走是确定性趋势，关键问题是：**需求增速能否持续快于成本下降速度**——这是判断算力投资是否过剩的核心逻辑，也是你之前做的Acemoglu/Wachter框架想回答的问题。

### 三、2030年真正的核心争议：收入能不能接得住？

这才是你做过剩分析最需要盯的地方。

**Bull case的逻辑：**
摩根大通预计超大规模云商在2027年的资本支出将超过1.1万亿美元，但同时预测运营现金流将在2027年突破9000亿美元，这意味着盈利能力仍能维持。

**Bear case的数学：**
Bain Capital估算，要让这些数据中心成本合理，AI相关业务到2030年需要产生2万亿美元的年收入——而ChatGPT推出三年后，AI收入仍仅约200亿美元，也就是说需要实现100倍增长。

**折旧的隐性炸弹：**
分析师估计，五大超大规模云商到2030年将把约2万亿美元AI相关资产放上资产负债表；假设5–6年使用寿命，折旧高峰期的年折旧负担将接近甚至超过这五家公司当前净利润的总和——利润不会崩塌，但在AI收入大规模兑现前，结构性利润率压缩几乎是确定性事件。

**激励结构导致的系统性过度投资：**
在过度投资的情形下，风险是全行业产能过剩，导致ROIC下滑和潜在减值，超大规模云商大概率能承受；但若低估AI变革性、投资不足，则面临被颠覆、失去竞争优势、甚至商业模式层面的生存风险——这种风险不对称性，从战略理性角度驱动着各方宁愿多建。

这是你之前Acemoglu模型框架的核心假设冲突所在：**如果企业级AI货币化速度慢于预期，5–7万亿的资本开支很难在2030年前找到充分的收入对应**，过剩就是大概率结果；反之，如果推理需求爆发（Agent大规模落地），现在的投入也许还不够。

综合多个来源，到2030年推理占**AI算力**的比例，**60–70%是相对扎实的区间**，80%是乐观上限，不是共识基准。

**"占比"本身有口径歧义。**

一个关键区分是：其他预测跟踪的是资本开支，而AIAI跟踪的是实际使用时长。训练集群的每GPU成本更高，因此即使推理的运行时主导地位更早到来，其资本支出占比仍会滞后——推理按计算时间超越训练的节点（约2027年），比按资本支出超越训练的节点（约2029年）早约两年。

这意味着如果你在讨论capex结构，用"使用时长"的推理占比数字会高估推理对资本开支的影响。

这意味着：训练型capex的合理性可以用"模型能力提升"这个较软的理由来辩护（即使没有立即货币化），而推理型capex必须由实际查询量来支撑，需求不兑现就是直接亏损。从这个意义上，"容错率降低"的判断是成立的——但它是结构性逻辑，目前还没有看到对这一点做过直接量化的研究。

## 推理成本 vs 数据中心投资：区别在哪里

### 从谁的视角看

**推理成本**是**用户/企业视角**的概念：你每调用一次API、每生成一个token，需要付出多少钱。这是一个**运营支出（OpEx）** 的概念。

**数据中心投资**是**供给侧/基础设施视角**的概念：云厂商、超大规模云商为了能跑这些推理任务，需要建多少机房、买多少GPU、拉多少电。这是一个**资本支出（CapEx）** 的概念。

---

### 两者的关系

可以用一个简单的链条来理解：

```
用户推理需求增长
       ↓
推理调用量 × 每次计算量 = 推理算力总需求
       ↓
需要多少GPU、多少机架、多少电来承载这个需求
       ↓
数据中心投资规模
```

所以**推理需求是数据中心投资的需求侧驱动之一**，但投资规模还取决于其他很多因素（训练需求、利用率假设、冗余系数、芯片世代等）。

---

### 最关键的差异：方向相反的趋势

这里有一个非常容易被混淆的地方：

**推理成本在快速下跌**，而**数据中心投资在快速上涨**——两者同时成立，并不矛盾。

原因是：

推理成本下降靠的是**算法效率提升**（蒸馏、量化、MoE架构、KV Cache等），单位token的计算消耗越来越少。但**总调用量的增长远超效率改善的速度**，所以总算力需求仍然暴增，数据中心还是要继续建。

这正好对应Jevons悖论（Jevons Paradox）——效率提升导致成本下降，反而刺激需求更快增长，总资源消耗不减反增。

斯坦福AI Index数据：AI推理成本在2022至2024年间下降约280倍，但这并没有减少数据中心投资，反而通过拉低使用门槛进一步扩大了需求规模。

---

### 对你的过剩分析的含义

这个区分对判断过剩风险很重要：

**推理成本持续下降** → 对企业端是好事，AI应用门槛降低，渗透率上升，但同时也压缩了云厂商的推理单价收入，需要靠量来弥补。

**数据中心投资** → 是供给侧的固定成本投入，一旦建成，闲置就是浪费，折旧照算。过剩风险发生在"建成的产能 > 实际推理调用量"这个层面，而不是"推理成本高不高"这个层面。

所以你在分析AI过剩的时候，需要分开跟踪两条曲线：**推理单价**（衡量货币化效率）和**数据中心利用率**（衡量产能是否被充分填满），这两个才是判断过剩是否真实发生的核心指标，而不是capex总量本身。

两者关系：生成式AI是企业AI的一个重要子集，但企业AI比生成式AI宽得多。

企业AI包括大量传统机器学习和深度学习应用，这些早于大模型时代就存在：

**预测类**：信用评分、欺诈检测、需求预测、客户流失预测——用历史数据预测未来，不生成内容。

**优化类**：供应链排程、动态定价、广告竞价——找最优解，不生成内容。

**识别类**：图像识别质检、异常检测、语音转文字（传统ASR）——分类判断，不生成内容。

这些是企业里实际跑了很多年的AI，产生了真实的ROI，但在市场报告里经常被单独计入"企业AI"而不计入"生成式AI"。

面向消费者的生成式AI——ChatGPT个人版、Midjourney、生成式AI短视频工具——技术上是生成式AI，但不算企业AI（它们计入消费者市场）。

- 生成式AI市场2025年约380–710亿美元（不同口径）

企业AI市场反而更大，因为它包含了大量非生成式的传统ML应用。

## AI公司的成本结构：完整拆解

### 先说训练和推理的归属

训练和推理**本身不是独立的成本科目**，它们是**驱动其他成本的活动**，具体体现在：

**训练** → 主要消耗GPU算力（租用云计算或自建数据中心），体现为**云计算费用**（OpEx）或**数据中心折旧**（CapEx折旧）。

**推理** → 每次用户调用都消耗GPU算力，体现为**推理成本/COGS（销货成本）**，是收入端直接对应的变动成本。

所以正确的理解是：训练和推理是**活动**，折旧是这些活动依托的**资产消耗方式**，两者不是并列关系。

---

### AI公司的完整成本结构

按财务逻辑分三层：

**第一层：COGS（直接成本）**

这是生产一单位产品的直接耗费，对AI公司来说主要是：

推理成本，即每处理一个token/一次API调用所消耗的GPU算力费用。这是OpenAI毛利率只有33%的核心原因——2025年推理成本84亿美元，直接压低毛利。

另外还有数据成本（语料采购、清洗）、人工标注（RLHF所需的人工反馈）、以及第三方API费用。

**第二层：OpEx（运营支出）**

训练成本大部分在这里体现（如果用云计算租GPU）。训练不像推理那样持续发生，而是阶段性的大额支出，但在会计上通常**计入当期费用**而非资本化。

研发费用：模型架构研究、安全对齐、后训练（RLHF/DPO）。

人员成本：顶级AI研究员薪酬极高，加上股权激励（SBC），这也是为什么OpenAI的GAAP亏损比non-GAAP亏损高出很多的原因之一。

**第三层：CapEx及其折旧**

如果公司**自建数据中心**或**购买GPU**，就会产生资本支出，然后按使用年限折旧（GPU通常3–5年）。

Anthropic和OpenAI目前主要靠云计算（AWS、Azure、Google Cloud），所以折旧不是主要科目，租用费用更多体现在COGS和OpEx里。但随着它们自建基础设施的动作增多（比如Anthropic与Google签了TPU协议），折旧会越来越重要。

---

### 机会成本怎么理解

这个更偏向于**投资者分析视角**，而非公司财务报表科目。

对于投资者，AI公司融到的几十上百亿资金如果不投AI，可以买国债或其他资产，所以存在机会成本。但对公司本身的损益表，机会成本不显示。

## AI公司盈亏平衡的基本公式

### 最简洁的形式

```
收入 = COGS + OpEx + CapEx折旧
```

展开就是：

```
调用量 × 单价 = 推理成本 + 训练成本 + 人员研发 + 数据中心折旧
```

---

### 每个变量的驱动逻辑

**左边：收入**

```
收入 = 用户数 × 使用强度 × 单token价格
```

这三个变量方向相互制约——单价在持续下降（"LLMflation"，每年约10倍降速），所以要打平，必须靠用户数和使用强度的增长来对冲。

**右边：成本**

```
总成本 = α×调用量 + β（固定）
```

其中：
- 推理成本（α×调用量）是**变动成本**，随使用量线性增长
- 训练、人员、折旧是**准固定成本**，短期不随调用量变化

这意味着打平的关键不是收入绝对值，而是**单位经济模型**（Unit Economics）能不能成立。

---

### 单位经济的打平公式

真正决定AI公司能不能活的，是每一单位收入能不能覆盖边际成本：

```
毛利率 = （单价 - 推理成本/token）/ 单价 > 0
```

然后用毛利去覆盖固定成本：

```
毛利润总额 > 训练 + 人员 + 折旧
```

以OpenAI为例：
- 单价在下降（竞争压力+自我降价争市场）
- 推理成本也在下降（算法优化）
- 但现在单价下降速度 > 推理成本下降速度 → 毛利率被压缩
- 同时固定成本（训练规模、人员）还在上升

所以当前亏损的本质是：**毛利率不够厚，撑不住固定成本底座**。

---

### 打平需要的临界条件

整理成三个必要条件，缺一不可：

**条件一：推理毛利为正且足够厚**

```
单token收入 > 单token推理成本
且差值 × 总调用量 > 固定成本总和
```

这要求规模足够大——固定成本是个坑，调用量越大，每单位分摊的固定成本越少。

**条件二：规模效应要快过价格战**

```
调用量增速 > 单价下降速度
```

如果单价每年跌10倍，调用量必须每年涨10倍以上才能维持收入不缩水。目前整个行业还在这个轨道上，但边际在收窄。

**条件三：训练成本不能无限制增长**

```
每代模型训练成本增速 < 该模型带来的收入增量
```

这是Anthropic相对OpenAI的核心优势所在——OpenAI预计2030年年训练成本约1250亿美元，Anthropic同期约300亿美元，后者的训练成本占收入比低得多，打平路径更短。

---

### 一个直观的杠杆图

```
价格下降         调用量增长
    ↘               ↗
        收入曲线
            ↕ 要超过
        成本曲线
    ↗               ↘
推理成本下降      固定成本上升
（算法优化）      （训练+人员+折旧）
```

打平发生的条件是：**收入曲线和成本曲线的交叉点**，而这个交叉点的时间取决于——规模效应能不能在固定成本失控之前到来。

OpenAI自己给的答案是2030年现金流转正，Anthropic更乐观，预计2027年自由现金流转正。市场的共识判断是两者都偏乐观，核心风险是**推理单价下降速度超预期**（DeepSeek效应持续），导致收入曲线比预期更平，打平时间推后。

## 核心恒等式的经济含义

你的框架本质上是一个**资产定价约束**，不是会计意义上的损益打平：

```
年化收入 ≥ (δ + r) × K
```

其中 K 是存量AI资本，δ 是经济折旧率，r 是要求回报率。

这个公式的经济含义是：**AI资产必须在自身消耗殆尽之前，同时偿还占用资本的机会成本**。这和普通会计打平（收入 > 成本）是两回事——会计打平不要求资本有回报，只要求不亏钱；这个框架要求资本得到充分补偿。

所以你的框架回答的问题是：**AI投资在资本市场意义上是否合理**，而不只是企业经营层面是否盈利。这是更严格的标准，也是判断过剩的正确切入点。

---

## δ 和 r 加总的内在逻辑

你说"δ 管资产本身在消失，r 管占用的钱本可以去别处挣"，这个表述非常准确。更技术性的说法是：

```
(δ + r) = 资本的用户成本（User Cost of Capital）
```

这是Hall-Jorgenson（1967）的经典框架，但AI语境下有两个重要变形：

**第一，δ 在AI里是内生的。** 普通基建的折旧率由物理磨损决定，相对稳定。AI硬件的δ 由技术迭代速度决定——当Blackwell出来，H100的经济价值不是线性折旧，而是阶梯式贬值。Wachter把这个额外贬值风险折算进r_a里（即15%里的额外10个点），是一种简化处理；更严格的做法是把它拆成：

```
δ_AI = 物理折旧 + 技术性过时风险溢价
r_AI = 无风险利率 + 股权/债务风险溢价
```

两者合计28–33%，但来源不同，对政策含义也不同。

**第二，r 的边际化很关键。** 你提到资金从五大厂自有现金流转向私募信贷，这个观察非常重要。WACC是**存量资本的加权平均**，但判断新增投资是否合理应该用**边际资本成本**。私募信贷利差~6.2个点加上基准利率，债务成本已接近10–11%，这意味着边际融资成本已经超过大部分超大厂自己的WACC。用10%作下沿是正确选择。

## 你的框架隐含的几个可以明确的假设

**假设一：K 是存量还是增量？**

如果K是2025–2030年累计投入的5–7万亿美元，那(δ+r)×K是对这批资产整个生命周期内每年需要产生的收入。但问题是这批资产不是同时投入的，有时间分布——早期投入的资产到2030年已经折旧一部分，晚期投入的还很新。严格来说需要对K做年份加权，否则会系统性高估2030年的门槛。

你现在用的方式（取存量K×(δ+r)）是保守估算，偏高沿，方向没问题，但在敏感性分析里值得标注。

**假设二：收入是年度流量还是永续？**

JPMorgan的650B/年是永续收入门槛，隐含假设是2030年之后收入不再增长。如果收入在2030年后仍有增长，那实际需要的2030年收入可以低于这个门槛。这是一个对多头最有利的反驳——但你可以用DCF逻辑封住：增长本身也需要持续投资，如果持续投资的边际回报递减，永续假设是合理的保守估计。

**假设三：r 是统一的还是分层的？**

不同投资主体的r不一样——超大厂自有现金流的机会成本约8–9%，私募信贷约10–11%，股权投资者要求15%+。你取10%和15%作区间，其实隐含着两个不同的投资主体视角，混在一起用需要说清楚：

## 一个可以加入框架的修正项

---

## 为什么不能双重计入风险

Wachter 的 r_a = 15%，其中多出来的 10 个点（相对于普通资本的 5%）是在给以下不确定性定价：

- 收入能不能兑现
- 技术过时风险
- 需求不确定性

但在完整企业框架里，这些风险**已经通过其他方式被显性处理了**：

COGS 里的推理成本是实际发生的，不是预期值；OpEx 里的训练成本也是实际支出；人工成本是真实合同，不是概率加权。

也就是说，完整企业框架已经在**现金流层面**把不确定性的实现值算进去了。如果 r 里再加风险溢价，等于对同一个不确定性收了两次费。

---

## 两个框架的 r 应该分别是什么

**宏观框架 (δ+r)×K 里的 r：**

可以用 10–15%，因为这个框架**没有显性列出运营成本**，风险溢价是在补偿那些没被计入的不确定性。这里 r 是"全包价"——既管机会成本，也管收入不兑现的风险。

**完整企业框架里的 r：**

应该用 **WACC**，大约 8–9%（超大厂）或 10–11%（边际债务融资），不加额外风险溢价。因为运营层面的风险已经在 COGS 和 OpEx 的实际数字里体现了，r 只需要管"这笔钱本可以去别处挣多少"这一件事。

---

## 用公式说清楚

宏观框架实际上是完整框架的压缩版：

```
(δ + r_高) × K
≈ COGS + OpEx + (δ + r_低) × K + 风险补偿
```

左边用高 r 把右边的运营成本和风险都打包进去了。所以两个框架不是独立的，是同一件事的不同展开方式，**不能混用 r**。

---

## 实操建议

你的分析里如果同时用两个框架，需要明确标注：

```
宏观框架：r = 10–15%（全包，含风险溢价）
企业框架：r = WACC = 8–10%（纯机会成本）
```

否则审稿人或读者很容易质疑你在企业框架里用了 15% 的 r，会被认为重复计算风险、人为抬高门槛。这个细节值得在框架说明里单独交代一句。

---

## 毛利率的标准定义

```
毛利率 = (收入 - COGS) / 收入
```

COGS（销货成本）里**包含什么**，取决于这项成本是否与**直接生产产品/服务**相关。

---

## AI公司的COGS具体包含什么

**肯定包含：**

推理算力成本——每生成一个token消耗的GPU算力，这是最直接的变动成本，直接对应每一笔收入。

数据中心托管费——租用AWS/GCP的云计算费用，属于直接服务成本。

与服务交付直接相关的折旧——如果公司**自建数据中心或购买GPU**，这部分硬件折旧应该进入COGS，因为它是生产服务的直接工具。

内容审核、安全过滤等直接服务成本。

**不包含在COGS里（进入OpEx）：**

研发人员薪酬——工程师、研究员开发模型，属于研发费用（R&D），不是直接生产成本。

训练成本——训练是研发活动，通常计入R&D，不进COGS。

销售、市场、行政人员薪酬——进入SG&A。

---

## 所以你的问题的直接答案

**毛利率里不只减人力成本，也不需要减所有折旧——只减与直接服务交付相关的成本。**

具体来说：

```
AI公司毛利 = 收入
           - 推理算力费用（最大项）
           - 直接服务相关折旧（自建基础设施时）
           - 数据/API等直接成本
           （不减研发人员薪酬）
           （不减训练成本）
           （不减SG&A）
```

---

## 为什么OpenAI毛利率只有33%

正是因为推理成本太重：

```
收入：~250亿美元（2026年化）
推理COGS：~141亿美元
→ 毛利润：~109亿美元
→ 毛利率：~33%
```

研发人员薪酬、训练成本、SBC都还没减，这些全在OpEx里，减完之后才是运营亏损的270亿美元。

---

## 一个容易混淆的地方

有时候你会看到AI公司报告两个不同的"毛利率"：

**GAAP毛利率**：严格按会计准则，有时候把某些人工成本（比如直接服务人员）算进COGS，毛利率偏低。

**Non-GAAP毛利率**：剔除SBC、某些折旧等非现金项目，毛利率偏高。

OpenAI的33%是接近GAAP口径的数字。如果剔除非现金项目，毛利率会更好看一些，但推理成本是真实的现金支出，剔除不了。

---

## 对你框架的含义

这个定义对你的分析有一个直接推论：

**毛利率能不能随规模扩大而提升**，取决于推理成本的下降速度能不能快过单价下降速度。人工成本在这个等式里几乎不起作用，折旧也只是在自建基础设施之后才变得重要。

所以判断AI公司盈利路径的核心指标，就是这一个比率：

```
推理成本/token 的下降速度
vs
API单价/token 的下降速度
```

前者快于后者 → 毛利率扩张 → 规模效应开始发挥 → 打平路径存在。
后者快于前者 → 毛利率压缩 → 越卖越亏 → 需要持续外部融资。

目前行业处于后一种状态，这是OpenAI到2030年才能打平的根本原因。
